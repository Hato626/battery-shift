# 电池换班簿 · Battery Shift

一个无需账号、无需安装依赖的 Windows 本地电池台账。记录电池组现在装在哪台设备、哪些组等待充电，以及下一次轮换可以用哪一组。

**状态由你记录，软件不检测硬件、不读取电量，也不推断容量或健康度。**

## 开始使用

1. 下载并完整解压项目到一个自己可写的目录，例如“文档\电池换班簿”。不要放在 `Program Files`。
2. 双击 **`start.cmd`**。Windows 自带的 PowerShell 5.1 会启动本地服务，并打开默认浏览器。
3. 保持启动窗口开启，在浏览器使用 `http://127.0.0.1:8767`。
4. 可以从空台账开始，也可以点击“体验示例台账”。示例只有自制的蓝、绿、橙三组电池和一台鼠标，可以撤销回到空台账。

普通使用**不需要 Node.js、npm、Python、互联网或管理员权限**。支持 Windows 10/11 和现代 Edge、Chrome；不要直接双击 `app/index.html`。关闭启动窗口就会停止服务，已经保存的台账不受影响。

## 能做什么

- **单体与固定组**：每节电池独立编号、标签；一节也能单独成组。可记录尺寸、化学类型、存放位置和备注。
- **设备与多个槽位**：按尺寸、数量和化学类型匹配；一个组始终只能处于一个槽位。
- **原子换班**：取出旧组、设定旧组状态、装入新组，在同一次保存中完成。也支持仅取出。
- **充电与退役**：待用、使用中、待充电、充电中、退役五种状态；只有确认充电完成才累计次数。退役组不能装入设备。
- **轮换建议**：优先显示最久未上场的兼容待用组，次数作为次级排序。建议不等同于电池健康判断。
- **搜索与纠错**：搜索组名、单体标签、位置、备注；编辑资料；连续撤销最近 10 步，撤销也保留记录。
- **本地历史与备份**：最近 500 笔操作；完整 JSON 导出、检查后恢复；导入后可以撤销到导入前台账。

组内电池是固定搭档。需要改组时，先从设备取出、结束充电，再编辑成员标签或数量。首版不提供跨组拖拽单体、硬件充电器联动或云同步。

## 一个完整流程

1. 给两节 AA NiMH 电池分别贴上“蓝 01”“蓝 02”，新建“蓝组”，逐行填写标签。
2. 新增“游戏手柄”，主槽设为 2 节 AA / NiMH。
3. 点击空槽的“装入电池”，选择蓝组。
4. 蓝组需要充电时，点击“换班 / 取出”，装入另一个待用组，把蓝组标为待充电。
5. 给蓝组充电，点击“开始充电”；实际完成后点击“充电完成”。
6. 定期使用左下角“导出备份”，把文件保存到另一个目录或磁盘。

## 数据放在哪里

默认保存于项目目录内：

```text
data/state.json           当前台账
data/state.previous.json  上一次成功保存的副本
data/server.lock          同一数据目录的进程独占锁
```

每次操作先校验状态与引用，再检查修订号，把完整新状态写入临时文件，最后用文件系统原子替换正式文件。多浏览器窗口同时编辑会触发修订冲突，避免静默覆盖。多个服务实例不能同时写同一数据目录。

备份包含所有电池、设备、最近历史与撤销快照，可能包含你写下的设备名称和备注。请按自己的隐私需要保管。数据文件与测试目录已从 Git 排除。

导入只接受 `schemaVersion: 1`，并检查编号、单体唯一性、设备引用、组规格、状态和撤销快照。未知版本拒绝导入，不自动猜测迁移方式。单份备份/写入请求上限 8 MB；最多 2,000 组、2,000 台设备、每组 24 节、每台设备 20 个槽位。含撤销快照时可能先达到大小上限，首版定位于家庭或小型工作室。

如果当前文件损坏，软件会停止加载，不会自动覆盖它。恢复方法：

1. 关闭启动窗口。
2. 复制整个 `data` 目录到别处留存。
3. 将完好的外部备份复制为 `data/state.json`；或者检查后使用 `state.previous.json` 的副本。
4. 重新启动并检查历史。

## 启动选项与常见问题

默认端口占用时，可以在项目目录终端运行：

```powershell
.\start.cmd -Port 8768
```

不自动打开浏览器、指定其他台账目录：

```powershell
.\start.cmd -NoBrowser -Port 8768 -DataDir "D:\我的台账\电池"
```

- **启动后不见网页**：查看启动窗口是否报错，手动打开窗口显示的 `127.0.0.1` 地址。不要改成局域网 IP 或 `localhost`。
- **公司策略禁止脚本**：启动器仅为当前进程指定执行策略，不修改系统策略；组织策略仍可能阻止运行。
- **服务重启后原网页不能保存**：刷新网页，重新建立本地会话。
- **移动或更新程序**：先导出备份，保留 `data` 目录，把其余源码文件一起移动或更新。

服务只绑定 `127.0.0.1`，校验 Host、Origin 和每次启动生成的写入会话 token；只提供固定的页面资源，不把 `data` 或项目根目录作为静态网站暴露。它适合单机使用，不是互联网或局域网服务器。

## 开发与测试

开发测试需要 Node.js 20+。运行时没有第三方依赖，开发测试使用 Playwright。

```powershell
npm ci
npm test
npm run test:ui
```

UI 测试默认使用已安装的 Microsoft Edge，并实际通过 `start.cmd` 启动 Windows PowerShell 5.1。测试在 `work/验收 带空格-*` 内建立独立副本与测试数据，验证中文和空格路径，不写真实 `data`。截图与结果在 `work/artifacts`。

没有 Edge 时可以使用 Playwright Chromium：

```powershell
npx playwright install chromium
$env:BROWSER_CHANNEL = 'chromium'
npm run test:ui
```

可用 `TEST_PORT` 环境变量更换测试端口。Windows GitHub Actions 配置见 `.github/workflows/ci.yml`，本地已执行结果见 [TEST_REPORT.md](TEST_REPORT.md)。远程 CI 是否通过，以 GitHub 实际运行结果为准。
